# Практическая работа № 6. Классификация текстов

## Цель работы

Освоить основные этапы обработки текстовых данных и разработать классификатор текстов с использованием TF-IDF и наивного байесовского алгоритма.

## Ход работы

**1. Очистка текста**

Реализована функция `clean_text()`, которая приводит текст к нижнему регистру, удаляет цифры и знаки пунктуации, разбивает текст на слова, удаляет стоп-слова и выполняет стемминг с помощью SnowballStemmer для русского языка.

**2. Токенизация и стемминг**

Токенизация выполняется регулярным выражением. Стемминг позволяет привести разные формы слов к общей основе, уменьшая количество уникальных признаков.

**3. Векторизация текста**

Для преобразования текстов в числовые векторы используется `TfidfVectorizer`. Параметр `min_df=1` позволяет учитывать слова, встречающиеся хотя бы в одном документе, а `max_df=0.9` исключает слова, встречающиеся более чем в 90% документов. Также используется `ngram_range=(1, 2)` для учёта отдельных слов и пар соседних слов.

**4. Обучение модели**

В качестве классификатора используется `MultinomialNB` — наивный байесовский классификатор. Данные разделяются на обучающую и тестовую выборки в соотношении 70% к 30%. Для воспроизводимости результатов используется `random_state=42`.

**5. Оценка качества**

Качество классификации оценивается с помощью Accuracy, F1-score, отчёта классификации и матрицы ошибок.

Accuracy показывает долю правильно классифицированных текстов. F1-score учитывает точность и полноту классификации выбранного положительного класса.

## Анализ возможных ошибок модели

1. **Смешанная тональность.** В тексте одновременно присутствуют положительные и отрицательные оценки. Модель может неправильно определить общий смысл отзыва.

2. **Отрицание.** Конструкции вроде «не плохой» могут интерпретироваться неправильно, если модель недостаточно учитывает контекст.

3. **Редкие слова.** Незнакомые или редко встречающиеся слова получают недостаточно информации для правильной классификации.

4. **Недостаточный контекст.** Модель учитывает отдельные слова и пары слов, но не всегда понимает смысл всего предложения.

5. **Противоположные оценки.** Например, хороший товар при плохом обслуживании может получить неверную метку из-за сочетания признаков разных классов.

Эти причины являются гипотезами. Для подтверждения каждой из них необходимо сопоставить её с конкретными текстами, которые модель действительно классифицировала неправильно.

## Вывод

В ходе практической работы реализован пайплайн классификации текстов, включающий очистку, токенизацию, стемминг, TF-IDF-векторизацию и обучение наивного байесовского классификатора. Качество модели оценивается на тестовой выборке с помощью Accuracy и F1-score. Анализ ошибок позволяет определить ограничения модели и возможные направления её улучшения.
